# 236. Lowest Common Ancestor of a Binary Tree

← [[Work/LeetCode/index|LeetCode 题解]]

> 二叉树后序遍历的代表题。核心规律：**凡是需要子树信息回传给父节点的，一律用后序。**

Given a binary tree, find the lowest common ancestor (LCA) of two given nodes in the tree.

According to the definition of LCA on Wikipedia: "The lowest common ancestor is defined between two nodes `p` and `q` as the lowest node in `T` that has both `p` and `q` as descendants (**where we allow a node to be a descendant of itself**)."

**Example 1:**

```
Input:  root = [3,5,1,6,2,0,8,null,null,7,4], p = 5, q = 1
Output: 3
```

**Example 2:**

```
Input:  root = [3,5,1,6,2,0,8,null,null,7,4], p = 5, q = 4
Output: 5
Explanation: 节点可以是自己的祖先，所以 LCA 是 5 而不是 3
```

**Constraints:**

- The number of nodes in the tree is in the range `[2, 10^5]`
- `-10^9 <= Node.val <= 10^9`
- All `Node.val` are **unique**
- `p != q`，且 **p 和 q 一定存在于树中**

参考树形（后面反复用到）：

```
        3
       / \
      5   1
     / \  / \
    6   2 0  8
       / \
      7   4
```

---

## 💡 这是 DFS 还是 BFS？

**是 DFS，而且必须是「后序遍历」。**

原因很直接 —— LCA 这个信息**只能从下往上传**。你站在某个节点上，光看自己是判断不出来的，必须先问两个问题：

- 「左子树里有 p 或 q 吗？」
- 「右子树里有 p 或 q 吗？」

**先处理左右孩子、再处理自己 = 后序遍历（左 → 右 → 中）。**

BFS 在这题不好使 —— 层序是「一层层往下推」，天然自顶向下，拿不到子树的汇总信息。

---

## 💡 思路（大白话）

站在任意一个节点上，只问自己两个问题：「左边找到人了吗？」「右边找到人了吗？」

- **两边都找到** → 这两个人分居我的左右 → **我就是最近的共同祖先**
- **只有一边找到** → 他们都在那一边 → 把消息**原样往上传**
- **两边都没有** → 这棵子树跟我无关 → 往上报「没找到」

> 👨‍👩‍👧 **类比**：在家族树里找两个人的最近共同长辈。消息从下往上传，谁同时收到了来自左右两支的信号，谁就是那个分岔点。

---

## 解法一：后序递归（标准解）

```Python
class Solution:
    def lowestCommonAncestor(self, root, p, q):
        # 终止条件：走到空，或者撞上了 p / q 其中之一
        if not root or root is p or root is q:
            return root

        left  = self.lowestCommonAncestor(root.left,  p, q)   # 左
        right = self.lowestCommonAncestor(root.right, p, q)   # 右

        # 中：根据左右的回传结果做判断
        if left and right:      # 左右各找到一个 → p、q 分居两侧 → 我就是 LCA
            return root
        return left if left else right   # 只有一侧有 → 把它继续往上传
```

**核心就是那三行判断，逐个拆：**

| 左边返回 | 右边返回 | 含义 | 动作 |
|---|---|---|---|
| 非空 | 非空 | p、q 一边一个 | **`root` 就是答案**，返回自己 |
| 非空 | 空 | 两个都在左边 | 把左边的结果原样上传 |
| 空 | 非空 | 两个都在右边 | 把右边的结果原样上传 |
| 空 | 空 | 这棵子树里啥也没有 | 返回 `None` |

### 为什么 Example 2 也对？

`p = 5, q = 4`，而 4 就在 5 的子树里，答案应该是 5。

关键在终止条件里的 `root is p` —— 递归走到节点 5 时**直接返回 5，根本不往下探**。回到节点 3 那一层：左边收到 5、右边收到 `None` → 上传 5 → 最终答案 5。✅

这正好实现了题目定义里那句 **"we allow a node to be a descendant of itself"**。

> ⚠️ 这个提前返回**依赖题目保证 p、q 一定存在于树中**（Constraints 里写了）。如果不保证，比如 q 根本不在树里，这份代码会**错误地返回 p**。面试官很爱追问这一点，标准答法是加一个标记记录「是否两个都找到了」，最后再判断。

## 🧠 递归到底怎么想？（本题的认知难点）

> 最常见的困惑：**「函数只返回节点，又没返回 true / false，那到底是怎么判断的？」**

### ① 节点**就是** true / false

Python 里 `None` 是**假值**，任何节点对象都是**真值**。所以那行判断的实际含义是：

```Python
if left and right:        # 等价于 if (左边不是None) and (右边不是None)
```

**返回节点，等于免费附赠了一个布尔值。**「有没有找到」这个信息已经藏在「是不是 `None`」里了，不需要另外返回。

### ② 子问题的「契约」是什么

这才是真正的难点。大多数人默认这个函数的含义是「找 LCA」—— **其实不是**。它真正的契约是三句话：

| 情况 | 返回什么 |
|---|---|
| p 和 q **都在** root 这棵子树里 | 它们的 **LCA** |
| **只有一个**在（另一个在别处） | **那一个本身**（p 或 q） |
| **都不在** | `None` |

**注意第二行 —— 返回值在不同情况下含义是不一样的**，有时是「答案」，有时只是「我在这儿撞见了一个人」。这就是让人晕的根源。

但它能自洽，因为父节点拿到左右两份回执后，足以区分：

- **两边都非空** → 一个在左、一个在右 → 分岔点必然是**我自己** → `return root`
- **只有一边非空** → 那边要么装着 LCA、要么装着单个人 → **不管是哪种，原样往上转发就对了**
- **两边都空** → 我这片区域没人 → `None`

第二条是精髓：**父节点根本不需要知道传上来的是「LCA」还是「单个节点」，它只管转发。** 而到了最顶层，因为题目保证 p、q 都在树里，最终返回的一定是 LCA。

### ③ 为什么不返回 bool？可以，但要额外开变量

这是完全等价的 bool 版写法：

```Python
class Solution:
    def lowestCommonAncestor(self, root, p, q):
        self.ans = None

        def dfs(node):                         # 契约：这棵子树里有没有 p 或 q？→ bool
            if not node:
                return False
            left  = dfs(node.left)             # 左边有吗
            right = dfs(node.right)            # 右边有吗
            mid   = (node is p or node is q)   # 我自己是吗

            if left + right + mid >= 2:        # 三个信号凑够两个 → 我就是 LCA
                self.ans = node

            return left or right or mid        # 往上报："我这片有人"

        dfs(root)
        return self.ans
```

对比就清楚了：

| | 返回节点版 | 返回 bool 版 |
|---|---|---|
| 返回值携带的信息 | 「有没有」**+**「是谁」 | 只有「有没有」 |
| 答案怎么带出来 | 靠返回值一路传上去 | **必须存进 `self.ans`** |
| 代码行数 | 6 行 | 13 行 |

> 💡 **一句话：返回节点，是把「标志位」和「答案」合并成了一个返回值。** bool 版信息量不够，所以被迫用一个外部变量补上。

顺带一提，bool 版还有个好处：`mid` 显式表达了「我自己就是 p 或 q」，`>= 2` 把三种成立条件统一了，比 `root is p` 的提前返回更直白。两个版本都值得会。

### ④ 手动跑一遍：看着答案往上冒

拿 `p = 7, q = 4` 试（答案是 2）：

```
                    3
                   / \
   ⑤返回 2 ←───   5   1   ───→ ④返回 None（这片没人）
                 / \  / \
 ①返回None ←─  6   2  0   8
                   / \
                  7   4
          ②返回7 ↑     ↑ ③返回4
```

| 步 | 在哪个节点 | 左边收到 | 右边收到 | 判断 | 返回 |
|---|---|---|---|---|---|
| ① | 6 | None | None | 都空 | `None` |
| ② | 7 | — | — | **我就是 p**，提前返回 | `7` |
| ③ | 4 | — | — | **我就是 q**，提前返回 | `4` |
| ④ | **2** | `7` | `4` | **两边都有！** | **`2`** ⭐ |
| ⑤ | 5 | `None`(来自6) | `2` | 只有右边有 | `2`（转发） |
| ⑥ | 1 | None | None | 都空 | `None` |
| ⑦ | 3 | `2` | None | 只有左边有 | `2`（转发）✅ |

**看第 ④ 步** —— 答案是在节点 2 那里「诞生」的。之后第 ⑤、⑦ 步的节点 5 和 3 **根本不知道** `2` 是个 LCA，它们只是执行「只有一边非空 → 原样上传」这条规则，把它一路托举到了最顶上。

### ⑤ 递归的通用心法

**❌ 最大的误区：在脑子里展开调用栈。**
试图跟着「进左子树 → 再进左子树 → 再进…」一层层想下去，想到第三层必晕。**人脑不适合模拟栈。**

**✅ 正确姿势：信任契约（recursive leap of faith）。** 写任何递归，只回答三个问题：

| 三问 | 本题的答案 |
|---|---|
| **1. 契约** —— 这个函数返回什么？（写成一句人话） | 「都在就返回 LCA；只有一个就返回那一个；都没有返回 None」 |
| **2. 终止** —— 什么时候能直接给答案，不用再递归？ | 走到空 → `None`；撞上 p 或 q → 返回它自己 |
| **3. 单层** —— **假设左右子树的答案我已经拿到了且一定对**，怎么拼出自己的答案？ | 都非空 → 我是 LCA；一边非空 → 转发；都空 → `None` |

**第 3 步是核心：你只需要想清楚「一层」。** 下面几十层怎么跑的，交给「契约一定成立」这个信念 —— 就像调用别人写好的库函数，你不会去读它的源码。

### ⑥ 「拼答案」的代码写在哪，就是什么序

```Python
left  = dfs(root.left)     # 左
right = dfs(root.right)    # 右
if left and right: ...     # 中   ← "拼答案"的逻辑在这里 = 后序
```

写在两个递归调用**之后** = 后序 = 自底向上 = 能用到子树信息。

所以「要子树信息就必须后序」**不是什么规定，而是物理限制** —— 你不先递归，就压根拿不到 `left` 和 `right`。反过来，如果是「往下传参数」（比如传路径、传深度），那就写在递归调用**之前** = 前序。

## 解法二：BFS 建父指针 → 转化成 [[160. Intersection of Two Linked Lists]]

**从 p 一路往上到 root 是一条链，从 q 一路往上到 root 也是一条链，这两条链在 LCA 处相交 —— 这就是相交链表。**

```
p=7 往上：7 → 2 → 5 → 3
q=4 往上：4 → 2 → 5 → 3
              ↑ 从这里开始重合 → LCA = 2
```

BFS 在这里的作用是**先扫一遍全树，记下每个节点的爸爸**：

```Python
from collections import deque

class Solution:
    def lowestCommonAncestor(self, root, p, q):
        # ① BFS 建 {子节点: 父节点} 映射
        parent = {root: None}
        dq = deque([root])
        while p not in parent or q not in parent:
            node = dq.popleft()
            if node.left:
                parent[node.left] = node
                dq.append(node.left)
            if node.right:
                parent[node.right] = node
                dq.append(node.right)

        # ② 把 p 的所有祖先塞进 set（= 160 的哈希解法）
        ancestors = set()
        cur = p
        while cur:
            ancestors.add(cur)
            cur = parent[cur]

        # ③ q 往上爬，第一个撞进 set 的就是 LCA
        cur = q
        while cur not in ancestors:
            cur = parent[cur]
        return cur
```

代码长得多，但有两个实战价值：

1. **不递归，不会爆栈**（见下方易错点 2）
2. 如果要查**很多对** (p, q) 的 LCA，parent 表建一次就能反复用；解法一每次都得重扫全树

---

## 复杂度

| 解法 | 时间 | 空间 | 备注 |
|---|---|---|---|
| 后序递归 | $O(n)$ | $O(h)$ | 树退化成链表时 $h = n$ |
| BFS + 父指针 | $O(n)$ | $O(n)$ | 迭代，无栈深风险 |

## ⚠️ 易错点

1. **必须后序，不能前序。** 前序是自顶向下，拿不到子树的汇总结果。记住通用规律：**要子树信息 → 后序；要往下传参数 → 前序。**
2. **递归深度**。Constraints 写了节点数最多 $10^5$，而 Python 默认递归上限是 1000。LeetCode 平台调高了所以能过，**本地跑要加**：
   ```Python
   import sys
   sys.setrecursionlimit(10**6)
   ```
   换成 C++ 后这个问题更凶 —— C++ 不会友好地抛异常，而是**直接栈溢出段错误**，报错信息基本没用。所以要心里有数：解法二是保底方案。
3. **比的是节点不是值**（同 [[160. Intersection of Two Linked Lists]]）。虽然本题 `Node.val` 唯一，用值比也能过，但养成用 `is` 的习惯。
4. **别忘了 p、q 必须存在这个前提**（见上文）。
