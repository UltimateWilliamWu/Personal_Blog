# 236. Lowest Common Ancestor of a Binary Tree

← [[Work/LeetCode/index|LeetCode 题解]]

> 二叉树后序遍历的代表题。核心规律：**凡是需要子树信息回传给父节点的，一律用后序。**

Given a binary tree, find the lowest common ancestor (LCA) of two given nodes in the tree.

According to the definition of LCA on Wikipedia: "The lowest common ancestor is defined between two nodes `p` and `q` as the lowest node in `T` that has both `p` and `q` as descendants (**where we allow a node to be a descendant of itself**)."

**Example 1:**

```
Input:  root = [3,5,1,6,2,0,8,null,null,7,4], p = 5, q = 1
Output: 3
```

**Example 2:**

```
Input:  root = [3,5,1,6,2,0,8,null,null,7,4], p = 5, q = 4
Output: 5
Explanation: 节点可以是自己的祖先，所以 LCA 是 5 而不是 3
```

**Constraints:**

- The number of nodes in the tree is in the range `[2, 10^5]`
- `-10^9 <= Node.val <= 10^9`
- All `Node.val` are **unique**
- `p != q`，且 **p 和 q 一定存在于树中**

参考树形（后面反复用到）：

```
        3
       / \
      5   1
     / \  / \
    6   2 0  8
       / \
      7   4
```

---

## 💡 这是 DFS 还是 BFS？

**是 DFS，而且必须是「后序遍历」。**

原因很直接 —— LCA 这个信息**只能从下往上传**。你站在某个节点上，光看自己是判断不出来的，必须先问两个问题：

- 「左子树里有 p 或 q 吗？」
- 「右子树里有 p 或 q 吗？」

**先处理左右孩子、再处理自己 = 后序遍历（左 → 右 → 中）。**

BFS 在这题不好使 —— 层序是「一层层往下推」，天然自顶向下，拿不到子树的汇总信息。

---

## 💡 思路（大白话）

站在任意一个节点上，只问自己两个问题：「左边找到人了吗？」「右边找到人了吗？」

- **两边都找到** → 这两个人分居我的左右 → **我就是最近的共同祖先**
- **只有一边找到** → 他们都在那一边 → 把消息**原样往上传**
- **两边都没有** → 这棵子树跟我无关 → 往上报「没找到」

> 👨‍👩‍👧 **类比**：在家族树里找两个人的最近共同长辈。消息从下往上传，谁同时收到了来自左右两支的信号，谁就是那个分岔点。

---

## 解法一：后序递归（标准解）

```Python
class Solution:
    def lowestCommonAncestor(self, root, p, q):
        # 终止条件：走到空，或者撞上了 p / q 其中之一
        if not root or root is p or root is q:
            return root

        left  = self.lowestCommonAncestor(root.left,  p, q)   # 左
        right = self.lowestCommonAncestor(root.right, p, q)   # 右

        # 中：根据左右的回传结果做判断
        if left and right:      # 左右各找到一个 → p、q 分居两侧 → 我就是 LCA
            return root
        return left if left else right   # 只有一侧有 → 把它继续往上传
```

**核心就是那三行判断，逐个拆：**

| 左边返回 | 右边返回 | 含义 | 动作 |
|---|---|---|---|
| 非空 | 非空 | p、q 一边一个 | **`root` 就是答案**，返回自己 |
| 非空 | 空 | 两个都在左边 | 把左边的结果原样上传 |
| 空 | 非空 | 两个都在右边 | 把右边的结果原样上传 |
| 空 | 空 | 这棵子树里啥也没有 | 返回 `None` |

### 为什么 Example 2 也对？

`p = 5, q = 4`，而 4 就在 5 的子树里，答案应该是 5。

关键在终止条件里的 `root is p` —— 递归走到节点 5 时**直接返回 5，根本不往下探**。回到节点 3 那一层：左边收到 5、右边收到 `None` → 上传 5 → 最终答案 5。✅

这正好实现了题目定义里那句 **"we allow a node to be a descendant of itself"**。

> ⚠️ 这个提前返回**依赖题目保证 p、q 一定存在于树中**（Constraints 里写了）。如果不保证，比如 q 根本不在树里，这份代码会**错误地返回 p**。面试官很爱追问这一点，标准答法是加一个标记记录「是否两个都找到了」，最后再判断。

## 解法二：BFS 建父指针 → 转化成 [[160. Intersection of Two Linked Lists]]

**从 p 一路往上到 root 是一条链，从 q 一路往上到 root 也是一条链，这两条链在 LCA 处相交 —— 这就是相交链表。**

```
p=7 往上：7 → 2 → 5 → 3
q=4 往上：4 → 2 → 5 → 3
              ↑ 从这里开始重合 → LCA = 2
```

BFS 在这里的作用是**先扫一遍全树，记下每个节点的爸爸**：

```Python
from collections import deque

class Solution:
    def lowestCommonAncestor(self, root, p, q):
        # ① BFS 建 {子节点: 父节点} 映射
        parent = {root: None}
        dq = deque([root])
        while p not in parent or q not in parent:
            node = dq.popleft()
            if node.left:
                parent[node.left] = node
                dq.append(node.left)
            if node.right:
                parent[node.right] = node
                dq.append(node.right)

        # ② 把 p 的所有祖先塞进 set（= 160 的哈希解法）
        ancestors = set()
        cur = p
        while cur:
            ancestors.add(cur)
            cur = parent[cur]

        # ③ q 往上爬，第一个撞进 set 的就是 LCA
        cur = q
        while cur not in ancestors:
            cur = parent[cur]
        return cur
```

代码长得多，但有两个实战价值：

1. **不递归，不会爆栈**（见下方易错点 2）
2. 如果要查**很多对** (p, q) 的 LCA，parent 表建一次就能反复用；解法一每次都得重扫全树

---

## 复杂度

| 解法 | 时间 | 空间 | 备注 |
|---|---|---|---|
| 后序递归 | $O(n)$ | $O(h)$ | 树退化成链表时 $h = n$ |
| BFS + 父指针 | $O(n)$ | $O(n)$ | 迭代，无栈深风险 |

## ⚠️ 易错点

1. **必须后序，不能前序。** 前序是自顶向下，拿不到子树的汇总结果。记住通用规律：**要子树信息 → 后序；要往下传参数 → 前序。**
2. **递归深度**。Constraints 写了节点数最多 $10^5$，而 Python 默认递归上限是 1000。LeetCode 平台调高了所以能过，**本地跑要加**：
   ```Python
   import sys
   sys.setrecursionlimit(10**6)
   ```
   换成 C++ 后这个问题更凶 —— C++ 不会友好地抛异常，而是**直接栈溢出段错误**，报错信息基本没用。所以要心里有数：解法二是保底方案。
3. **比的是节点不是值**（同 [[160. Intersection of Two Linked Lists]]）。虽然本题 `Node.val` 唯一，用值比也能过，但养成用 `is` 的习惯。
4. **别忘了 p、q 必须存在这个前提**（见上文）。
