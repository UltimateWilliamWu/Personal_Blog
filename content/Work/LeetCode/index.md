## 🧠 套路总结

目前这几题，背后其实只有 **3 个套路**：

| 套路 | 核心思想 | 题号 |
|---|---|---|
| **空间换时间** | 先把数据整理进「小本子」（哈希表 / 集合），把「逐个比对」变成「一次查询」 | 1、242、349 |
| **利用有序性** | 数据有序 → 每次能安全排除一半 | 704 |
| **双指针 / 自底向上** | 不额外开空间，靠指针的相对位置、或子问题往上回传来解 | 160、234、236 |

### 🧰 技巧速查

| 技巧 | 干什么用 | 出现在 |
|---|---|---|
| **快慢指针** | 找中点 / 判环 / 找倒数第 k 个 | 234 |
| **固定间距双指针** | 把「从后往前数」转换成「从前往后走」 | 160、234 |
| **反转链表**（存后路 → 掉头 → 双指针前移） | 需要倒着遍历时 | 234 |
| **递归三问**（契约 / 终止 / 单层） | 所有树与递归题的通用框架 | 234、236 |
| **后序遍历** | 需要子树信息回传给父节点时 | 236 |
| **区间三件套**（`right` 初值 / `while` 条件 / 收缩方式） | 二分的唯一真坑 | 704 |

> 💡 **如果只记一句话：**
> 暴力解法之所以慢，是因为它在**反复重新查找同一批东西**。所有快的解法都在干同一件事 —— 要么**提前把答案存好**（哈希），要么**每一步都多排除一些**（二分、双指针）。

## 🗺 刷题路线

当前语言策略：**Python 先行**（详见下方），瓶颈期再切 C++。

```
数组 → 链表 → 哈希 → 字符串 → 栈与队列 → 二叉树     ← Python，快速过，建模式库
                                          ↓ 切换点
回溯 → 贪心 → 动态规划 → 图                          ← C++ 为主
                                          ↑ 同时把前面的经典题用 C++ 重刷
```

**为什么这样切：** 前六块是**模式识别**，题目本身不难，Python 的低摩擦优势最大化；到了回溯 / DP，题目难度上来了，如果那时还没有 C++ 手感，会变成「算法难 + 语言生」双重打击。

**Python 拐杖警告** —— 这些「免费午餐」在 C++ 里都是要花代价的：

| Python 随手写 | C++ 的真实成本 |
|---|---|
| `sorted(s) == sorted(t)` | 得先 `sort()` 再比，且原串被改 |
| `Counter(s)` | 手写 `unordered_map<char,int>` 累加 |
| `nums[::-1]`、`nums[i:j]` | `reverse()` / 手动双指针，切片会**真拷贝** |
| **整数无限精度** | **`int` 会溢出，`long long` 也会 —— 必须主动想** |
| `heapq`（小顶堆） | `priority_queue` **默认大顶堆**，方向是反的 |
| `dict` 保持插入序 | `unordered_map` 无序，`map` 是红黑树序 |

最危险的是**溢出** —— Python 完全不会让你意识到这个问题存在，而它是 C++ 刷题最高频的 WA 来源之一。
