# 234. Palindrome Linked List

← [[Work/LeetCode/index|LeetCode 题解]]

> 快慢指针的模板题。核心矛盾：**单链表没有回头路，你得自己造一个「回头」的能力出来。**

Given the `head` of a singly linked list, return `true` if it is a palindrome or `false` otherwise.

**Example 1:**

```
Input:  head = [1,2,2,1]
Output: true
```

**Example 2:**

```
Input:  head = [1,2]
Output: false
```

**Constraints:**

- The number of nodes in the list is in the range `[1, 10^5]`
- `0 <= Node.val <= 9`

**Follow up:** Could you do it in `O(n)` time and `O(1)` space?

---

## 💡 问题的本质

回文判断的标准做法是**两头往中间夹**。但那需要能**从尾巴往回走** ——

- **双链表**有 `prev` 指针，天然能倒着走，这题就是送分题
- **单链表**只有 `next`，**根本没有回头路**

所以这题的全部难点就一句话：**怎么在单链表里造出「回头」的能力。** 一共三种造法：

| 造法 | 手段 | 空间 |
|---|---|---|
| ① 抄一份到数组 | 数组能随机访问，想回头就回头 | $O(n)$ |
| ② 借用栈 | 后进先出天然是倒序（**递归的调用栈也算**） | $O(n)$ |
| ③ 把指针方向掰过来 | 真的把后半段反转 | $O(1)$ ← **follow-up 的答案** |

---

## 🔑 前置技巧：快慢指针找中点

要反转「后半段」，先得知道**中点在哪**。答案是快慢指针。

**一句话：** 两个指针同时从头出发，`slow` 一次走一步，`fast` 一次走两步。**`fast` 到终点时，`slow` 正好在中点。**

> 🏃 **类比**：操场上两个人同时起跑，一个速度是另一个的两倍。快的跑完全程时，慢的刚好跑了一半。

```Python
slow = fast = head
while fast and fast.next:
    slow = slow.next
    fast = fast.next.next
```

### 偶数长度 `[1,2,2,1]`

```
起点   slow,fast
        ↓
        1 → 2 → 2 → 1 → None

第1轮   1 → 2 → 2 → 1 → None
            ↑    ↑
          slow  fast

第2轮   1 → 2 → 2 → 1 → None
                 ↑         ↑
               slow      fast(=None)
```

`fast` 变成 `None` → 停。**`slow` 落在后半段的第一个元素**，前半 `[1,2]`、后半 `[2,1]`，分得干干净净。

### 奇数长度 `[1,2,3,2,1]`

```
第2轮   1 → 2 → 3 → 2 → 1 → None
                ↑         ↑
              slow      fast
```

`fast` 还在但 `fast.next` 是 `None` → 停。**`slow` 落在正中间那个 `3` 上。**

中间元素会被算进后半段，比较时相当于**自己跟自己比**，永远相等，不影响结果。所以奇偶两种情况**不需要分开处理** —— 这是这个写法最舒服的地方。

> ⚠️ 循环条件必须是 `while fast and fast.next`，两个都要判：
> - 少了 `fast` → 偶数长度时 `fast` 已是 `None`，再访问 `fast.next` 直接崩
> - 少了 `fast.next` → 奇数长度时 `fast.next` 是 `None`，`fast.next.next` 崩

## 解法一：转数组（最直观，先会这个）

```Python
class Solution:
    def isPalindrome(self, head):
        vals = []
        cur = head
        while cur:
            vals.append(cur.val)
            cur = cur.next
        return vals == vals[::-1]
```

更能体现「两头夹」思路的写法：

```Python
        left, right = 0, len(vals) - 1
        while left < right:
            if vals[left] != vals[right]:
                return False
            left += 1
            right -= 1
        return True
```

$O(n)$ 时间、$O(n)$ 空间。**这本质上就是「把单链表变成双链表」** —— 数组本来就能双向走。面试时可以先说这个方案，再问「需要优化空间吗」。

## 解法二：递归（借调用栈回头）

**递归的「返回过程」天然就是在往回走。**

```Python
class Solution:
    def isPalindrome(self, head):
        self.front = head                # 从前往后的指针

        def check(node):
            if not node:
                return True
            if not check(node.next):     # ① 先一路递归到最后一个节点
                return False
            # ② 能走到这里，说明正在"回溯"—— node 是从后往前的！
            if node.val != self.front.val:
                return False
            self.front = self.front.next # ③ 前指针往后挪一格
            return True

        return check(head)
```

**关键在 ① 和 ② 之间那道坎：** 递归调用**之前** `node` 从前往后走，递归调用**返回之后**，`node` 就变成从后往前了 —— 因为栈是后进先出的。

于是 `node`（从后往前）和 `self.front`（从前往后）形成了一对**相向而行**的指针，跟数组的左右夹逼一模一样。

用[[236. Lowest Common Ancestor of a Binary Tree|递归三问]]套一下：

| 问题 | 本题的答案 |
|---|---|
| **契约**：函数返回什么 | 「从 `node` 到链尾这一段，跟 `self.front` 开始的那一段，是否对称」 |
| **终止**：什么时候直接给答案 | 走到 `None` → 返回 `True`（空段一定对称） |
| **单层**：怎么拼答案 | 先信任子问题的结论，再比自己这一对，然后把 `front` 往后挪 |

$O(n)$ 时间，$O(n)$ 栈空间。

> ⚠️ Constraints 写了最多 $10^5$ 个节点 —— **跟 236 一样有爆栈风险**，本地跑要 `sys.setrecursionlimit(10**6)`。

## 解法三：快慢指针 + 反转后半段（follow-up 的 $O(1)$ 答案）

**三步走：找中点 → 反转后半 → 两头往中间比。**

```Python
class Solution:
    def isPalindrome(self, head):
        # ① 快慢指针找中点
        slow = fast = head
        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next

        # ② 从 slow 开始反转后半段
        prev = None
        while slow:
            nxt = slow.next      # 先存好下一个，不然断了就找不回来
            slow.next = prev     # 掉头
            prev = slow          # prev 往前挪
            slow = nxt           # cur 往前挪
        # 循环结束时 prev 是反转后的新头

        # ③ 一个从头走，一个从反转后的头走
        left, right = head, prev
        while right:             # 用短的那半做终止条件
            if left.val != right.val:
                return False
            left = left.next
            right = right.next
        return True
```

### 反转过程可视化（后半段 `2 → 1`）

```
初始    prev=None    slow: 2 → 1 → None

第1步   nxt = 1
        2.next = prev(None)   →   prev: None ← 2      slow: 1

第2步   nxt = None
        1.next = prev(2)      →   prev: None ← 2 ← 1  slow: None

结束    prev = 1 → 2 → None    ← 新的头
```

**三行赋值的顺序是固定套路**，背下来：

```Python
nxt = cur.next      # 1. 存好后路
cur.next = prev     # 2. 掉头
prev = cur          # 3. 两个指针一起往前挪
cur = nxt
```

$O(n)$ 时间，$O(1)$ 空间 ✅

## 复杂度对比

| 解法 | 时间 | 空间 | 备注 |
|---|---|---|---|
| 转数组 | $O(n)$ | $O(n)$ | 最好想，面试先说这个 |
| 递归 | $O(n)$ | $O(n)$ | 巧妙，但有爆栈风险 |
| **快慢指针 + 反转** | $O(n)$ | $O(1)$ | **follow-up 要的答案** |

---

## ⚠️ 易错点

1. **反转时必须先存 `nxt`。** `slow.next = prev` 一执行，原来的 `next` 就丢了，链表当场断成两截。这是链表反转的头号坑。
2. **比较循环用 `while right`，不要用 `while left and right`。** 奇数长度时前半会比后半多一个（中间元素），拿**短的那半**做终止条件才对。
3. **解法三会破坏原链表。** 这题没要求保持原结构（不像 [[160. Intersection of Two Linked Lists]] 明确要求），但**面试官很可能追问「能还原吗」** —— 答案是把后半段再反转一次接回去。提前想好这句。
4. **`fast and fast.next` 两个条件都要判**（见上文）。
5. **单节点 `[1]`** 天然返回 `True`：`fast.next` 是 `None` 直接不进循环，`slow = head`，反转后只有一个元素，比一次就过。

## 📌 快慢指针是链表题的万能工具

这个技巧不止这一题用，记下来：

| 用法 | 怎么设 |
|---|---|
| **找中点** | slow 1 步 / fast 2 步 → fast 到头时 slow 在中点 |
| **判断有没有环** | 同上，有环则两者必定相遇（快的会套圈追上慢的） |
| **找倒数第 k 个** | fast 先走 k 步，然后两个同速走，fast 到头时 slow 就在倒数第 k 个 |

第三个其实就是 [[160. Intersection of Two Linked Lists]] 里「长的那条先走差值步」的同一招 —— **用两个指针的固定间距，把「从后往前数」转换成「从前往后走」**。单链表所有跟「末尾 / 中点 / 倒数第 k」相关的问题，基本都是这个套路。
